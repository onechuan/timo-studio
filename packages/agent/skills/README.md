# 内置创作 Skills

规划与口播阶段由代码按 `Production.brief.contentType` 选择目录，不依赖 Agent 自行发现 Skill。`src/skills/index.ts` 读取的顺序是：当前阶段共享方法 → 所选方向的 SKILL.md → 当前阶段方向参考。新建和重绘任务加载 `program-drawing/SKILL.md`，组合顺序为 PAGE_PROGRAM → 程序化绘图 Skill → 画面风格；旧 V1/V2 页面仍由兼容函数与 `visual-storytelling/SKILL.md` 支持。绘图协议不注入口播阶段。基础提示词负责角色、格式和阶段约束。

| 内容         | 文件                  | 用途                                           |
| ------------ | --------------------- | ---------------------------------------------- |
| 通用导演方法 | shared/planning.md    | 论点组织、材料取舍、原稿识别、可绘制的主体、构图与变化 |
| 通用口播方法 | shared/script.md      | 原稿保留、自然承接、断句和篇幅、自查           |
| 通用讲解     | general-narration/    | 一句核心回答与日常解释                         |
| 科普口播     | science-explainer/    | 因果链、必要条件、观测和机制的区别             |
| 产品介绍     | product-introduction/ | 真实功能、使用场景、有依据的价值               |
| 绘图与动画叙事 | visual-storytelling/ | 拍点与真实句子对齐、连续状态、空间关系、局部修复 |
| 程序化绘图 | program-drawing/ | V3 绘图 DSL、真实句级时间和确定性修复 |

此 README 不传给模型。新增或修改规则时，同步检查基础提示词是否存在相反的要求；保留当前 schema，不能通过文字规则引入未实现的工具或媒体能力。

## 参考帧言的取舍

本轮阅读本地 `frametell/packages/agent/prompts/PLANNER.md`、`PAGE.md`、`REVIEW.md`，将其中的讲解组织与检查思路按本项目重新表述。

| 参考方法                 | TimoTV 中的处理                                                       |
| ------------------------ | --------------------------------------------------------------------- |
| 从观众的问题组织论点     | 分镜先确定核心回答，再决定材料顺序与取舍                              |
| 贯穿对象、开场与结尾呼应 | 保持主体名称和比喻含义一致，结尾回答开场；原稿模式优先保留原文        |
| 每个拍点表达变化         | 模型生成 `TIMO.visual` 页程序，同一对象可持续绘制、移动、变形和切换状态       |
| 跟随真实配音安排画面     | 将已测量的句级起止时间注入引擎，页程序通过 `P.c/P.ce/P.cw` 对齐动作          |
| 自然口播、保留用户原稿   | 新稿按内容断句；原稿只拆分，不改字词顺序或混入 Visual                 |
| 页级检查                 | 提交前内容自查；实际截图、布局检查与独立视觉模型审片由审片流程承担 |

已将帧言绘图引擎以 AGPL 源码形式迁入 `packages/drawing-engine`，并在 TimoTV 上新增安全的 V3 绘图协议。`prompts/PAGE_PROGRAM.md` 在配音后生成受限的 `TIMO.visual` 程序；渲染器将引擎、风格和允许的组件内联到自包含文档，预览、审片、跳转与 MP4 导出共用 `renderAt(ms)`。V1/V2 矢量对象作为兼容页面仍可与 V3 混合播放。

## 参考短剧创作规范的取舍

参考本地 `huobao-drama/backend/workspace` 下的 script-rewriter、storyboard-breaker、prompt-generator 和 extractor 方法，按 TimoTV 协议重新编写：按理解节拍组织因果链、将抽象意图落到可见动作、保持主体和空间一致、局部修改保留有效内容。未复制其工具实现或 Mastra 加载机制。

不引入对白驱动、固定三秒切镜、8–15 秒视频任务、角色三视图或白底素材要求；对象按解释价值选取，不按剧情道具数量限制。跨页复用依靠 previousArtwork 参考和新页面显式定义，不代表已新增资产库或自动跨页运行时状态。规划不编造时间，绘图使用 TTS 实测 cues。Prompt 保留协议，Skill 维护方法，避免重复写互相冲突的规则。

## 验证边界

`tests/director.test.ts` 验证阶段和方向加载隔离、原始 topic 传递及已有结构约束。独立 Agent 的短场景验证仅用于发现规则冲突，不等同于真实 DeepSeek 的效果评测，也不保证精确时长。更换模型后，可用短材料、逐字原稿和资料稀少的产品三个场景重新做人工验收。
