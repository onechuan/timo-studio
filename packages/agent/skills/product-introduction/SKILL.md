# 产品介绍

围绕“谁在什么场景遇到问题 → 产品如何帮助 → 可核实的使用收益”组织内容。功能必须对应具体用户动作，收益必须能从资料支持的功能合理推出。用演示帮助理解，不堆宣传形容词。

资料不足时只陈述已知信息，删去缺乏依据的功能、价格、性能数字、客户证言及竞品比较。不可根据产品名称猜测能力。无需额外索要演讲稿；可围绕用户已给的定位收窄介绍范围。结尾只给资料支持的下一步，不杜撰网址、促销或购买入口。

分镜阶段使用 [分镜参考](references/planning.md)；写稿阶段使用 [口播参考](references/script.md)。运行时只提供当前阶段的参考正文，无需读取文件或执行命令。
