# 逐页绘图升级

用户反馈现有分镜与画面质量不足，希望参考帧言。根因是旧 `filmHtml` 完全不消费 visual，只把 beats 截为 16 字并排列成中心圆点关系图；提示词还明确要求沿用这一限制。

采用帧言的职责划分：导演先设计可解释的画面，批准后生成口播，真实配音决定句级时间，再逐页生成视觉对象。TimoTV 独立实现受约束矢量协议，不直接复制帧言引擎或执行模型生成的脚本。页面由大型插画组件、形状、SVG 路径、箭头和自动换行文字组成，按照 cueIndex 对应的真实起始时间确定性显现。支持横竖版，标题与字幕留出安全区域。

layout 表达主体特写、过程演示、左右对照、系统关系或时间推进；它用于指导生成，不是填充固定节点的模板。三种风格语法同时传入规划与绘图，保证色彩、主体和讲述方式一致。逐页输出经过 schema、边界、句子引用和文字尺寸校验；仅对校验失败做一次有限修复。结构校验不等于视觉审核，最终以关键帧截图检查辨识度、留白、文字与对象重叠。

流程增加 illustrating 阶段，每页生成后持久化，失败重试跳过已完成页面。新增 illustrate 操作用于旧项目或重绘：复用现有配音、字幕与时间，只重建画面和预览；脚本语义变化使对应画面失效，单纯换音色可继续用原画面。新任务仍受修订号与 jobId 所有权约束。

验证覆盖协议安全与兼容、逐句显现、反向 seek 的确定性、横竖屏、干净导出、逐页恢复、跨修订复用音频、桌面/手机绘图入口。使用现有三页作品做真实 DeepSeek 绘图与截图检查，保留既有配音；不自动批准待审批的长片，不部署或提交代码。
