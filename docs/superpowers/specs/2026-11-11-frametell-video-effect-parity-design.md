# TimoTV 与帧言视频效果对齐设计

## 目标

TimoTV 保留现有网页、项目、数据库、队列、模型设置、配音和失败恢复能力，把从已批准分镜到最终 MP4 的视觉制作链路升级为与帧言当前版本同源、同能力、同检查标准的实现。

本项目的“效果一样”定义为：在画幅、分镜、口播、真实配音时间、风格、绘图程序和引擎版本都固定时，TimoTV 与帧言必须生成视觉等价的关键帧和相同时间结构的 MP4；从相同主题独立调用生成模型时，不要求逐像素相同，但必须使用同一导演规则、风格语法、组件能力、页面检查和全片检查，达到同一质量区间。

## 范围

本次只迁移影响最终视频效果的能力：

- 帧言绘图运行时、全部当前风格包、通用组件和风格专用组件。
- 分镜和口播中与视觉策划、页面节奏、镜头语言有关的导演约束。
- Film Kit：为同一部影片生成并检查可跨页复用的角色、道具和场景组件。
- 按真实口播时间生成页面程序，包括逐笔文字、动态几何、镜头、Canvas、KaTeX、Three.js 和受控本地媒体。
- 页面运行检查、布局 lint、确定性检查、关键帧截图、独立视觉审片和最多两轮修正。
- 全片联系表检查、跨页一致性修正、预览和 1080p MP4 渲染。
- 页级检查点、失败恢复、旧项目兼容和可追溯的上游版本同步。

不迁移以下产品能力：

- 帧言桌面壳、CLI、品牌、工作台布局和对话界面。
- PDF、PPT、Word、图片等资料解析和联网研究。
- 成片后的拖动、缩放、改字、改色、出现时间调整和 Git 版本恢复。
- 帧言的发布文案、社区功能和安装分发方式。

## 方案选择

采用“共享帧言成片内核，保留 TimoTV 产品外壳”的方案。

不继续用 TimoTV 自有 JSON/SVG 协议逐项模仿帧言，因为这种方式会持续遗漏运行时、风格语法、Film Kit、镜头和检查闭环。也不把帧言 CLI 作为黑盒子进程调用，因为那会造成两套项目状态、恢复逻辑和产物目录，难以与 TimoTV 的数据库 revision 和 BullMQ 任务所有权保持一致。

帧言仓库是视觉能力的规范来源。第一轮对齐锁定帧言提交 `6145f7e3482628543bd6f2d68fe3b618d366213a`；后续升级必须先更新基准并重新通过全套视觉回归。TimoTV 内的 `packages/drawing-engine` 保留为可构建包，但通过明确的上游清单、基线哈希和少量适配补丁与帧言 `packages/engine` 同步。帧言导演中影响成片效果的规则迁移为 TimoTV 可持久化的端口和状态，而不是直接复制帧言的文件型项目管理。

## 总体架构

```text
TimoTV Web / API
       │  approved storyboard + narration settings
       ▼
ProductionService ── revision / job ownership / recovery
       │
       ▼
ProductionRunner
       ├─ Script + TTS ── measured cue timing
       ├─ Film Kit Director
       │    └─ write → engine check → visual review → keep passed components
       ├─ Page Director lanes
       │    └─ write → runtime/lint → snapshots → visual review → repair
       ├─ Whole-film Reviewer
       │    └─ contact sheet → cross-page fixes → recheck affected pages
       └─ Frametell-derived Renderer
            └─ preview / seek / screenshots / 1080p MP4
```

`ProductionService` 继续负责用户动作、版本冲突和任务申领；`ProductionRunner` 负责阶段顺序、检查点和恢复；`worker` 注入模型、视觉模型、配音、浏览器和存储；`drawing-engine` 只负责确定性视觉运行时。任何页面程序都不能直接访问数据库、Redis、模型密钥、Node API 或外部网络。

## 上游同步与许可

TimoTV 已使用 AGPL-3.0-only，并保留帧言绘图引擎来源说明。本项目增加一份机器可读的上游清单，至少记录：

- 帧言仓库提交哈希。
- 同步的 runtime、styles、lib、vendor、tools 和模板文件清单及内容哈希。
- TimoTV 必须保留的适配补丁，包括精确 cue 时间、资源逻辑 ID、CSP 和播放器桥接。
- 同步脚本的 dry-run 和 apply 模式；dry-run 在上游变化时列出新增、删除、修改和冲突文件。

引擎同步以行为等价为第一目标。基线未通过前不重写算法或重命名运行时 API。TimoTV 自有修改尽量放在适配层，减少以后同步新风格和修复的冲突。

## 数据契约

现有 `SceneProgramV3` 保留，新增影片级视觉状态：

```ts
type FilmVisualState = {
  upstreamRevision: string;
  engineRevision: string;
  style: DrawingStyle;
  filmKit?: {
    status: 'pending' | 'checking' | 'passed' | 'partial' | 'failed';
    source: string;
    sourceHash: string;
    components: FilmKitComponentResult[];
    sheetKey?: string;
  };
  wholeFilmReview?: {
    fingerprint: string;
    status: 'pending' | 'checking' | 'passed' | 'needs_attention' | 'failed';
    round: number;
    issues: ReviewIssue[];
    sheetKey?: string;
  };
};
```

每页 V3 记录继续包含源码、源码哈希、风格和 extras，并扩展检查指纹、页级 Agent 会话摘要、检查轮次、关键帧清单和恢复点。模型不能提供最终哈希、文件路径或审片结论；这些由可信宿主生成。

数据库仍保存结构化 Production 文档和对象存储 key。页面程序、Film Kit、截图和 MP4 作为当前 revision 的产物登记，旧任务只能读取自己的固定快照，不能覆盖较新 revision。

## 导演与生成流程

### 分镜和口播

TimoTV 保留现有用户确认流程，但分镜和口播提示词引入帧言中影响画面质量的约束：页面视觉动作、主体连续性、镜头变化、可画性、每页信息密度和真实时长预算。模型仍通过结构化 submit 输出，不获得文件系统或 shell。

### Film Kit

批准口播并得到真实时间后，系统根据分镜中的跨页主体生成 Film Kit 计划。需要在多页出现的角色、设备、场景或道具只定义一次。各组件分组并行生成，在独立检查页中执行：

1. 源码和允许 API 检查。
2. 引擎运行、确定性和布局 lint。
3. 联系表截图。
4. 独立视觉审片。
5. 最多两轮定点修正。

通过的组件合并为影片 Film Kit；单个组件失败时降级为页面内绘制，不阻塞整部影片。Film Kit 的源码和检查结果必须检查点持久化，任务恢复时不得重复生成已通过组件。

### 页面生成

每页 Agent 接收当前风格语法、绘图 API、可用组件签名、影片 Film Kit、完整分镜、真实 cue 时间、上一页视觉摘要和用户的长期创作要求。页面输出完整 V3 程序。

页面可并行生成，但同一 lane 的上下文必须携带相邻页信息，保证主体造型、颜色、空间方向和视觉隐喻连续。默认并发上限与模型、浏览器资源分离配置；并发不能改变最终页面顺序和检查指纹。

每轮页面检查固定执行：

1. 源码大小、注册 ID、API 白名单和资源清单校验。
2. 在固定 Chromium、固定字体和固定随机种子下运行。
3. 在 cue 边界、动作中点、镜头终点和页面末态截图。
4. 检测运行异常、非确定性、越界、字幕安全区、文字过小、裁切和明显遮挡。
5. 独立视觉模型检查主体、构图、层级、风格、口播对应关系和跨帧连续性。
6. 把必须修复的问题、时刻和截图交回原页面 Agent，最多修正两轮。

运行时或布局红色错误不得由用户直接接受。只有视觉建议或轻微一致性问题可以明确接受后继续。

### 全片检查

所有页面通过页级检查后生成全片联系表和时间摘要。全片 Reviewer 检查：

- 同一主体跨页漂移。
- 风格、线条、字体、强调色和背景不一致。
- 连续多页采用相同构图，或镜头节奏单调。
- 画面没有跟随口播变化、页面过早结束或末态不稳定。
- 页面衔接方向、色义和视觉隐喻冲突。

Reviewer 只返回页级问题和必须修复的时间点。系统只重开受影响页面，重新执行其页级检查，然后更新全片联系表。全片最多两轮；达到上限后保留已改善页面，并将仍存在的问题标记为等待用户确认。

## 渲染一致性

预览、暂停、seek、审片截图和导出必须调用同一 `renderAt(globalMs)`。页面局部时间由真实 cue 时间决定，不从字数重新估算。所有随机效果使用固定种子；字体、Chromium、设备像素比、画布尺寸和颜色空间在基准环境中固定。

固定输入基准要求：

- 横版 1920×1080 和竖版 1080×1920 各一组。
- 至少覆盖 whiteboard、chalkboard、warm-story、tech-dark、Three.js 风格和一个含本地图片的风格。
- 每个样本固定 storyboard、script、cue 时间、Film Kit、页面源码和引擎版本。
- 在相同时间点比较帧言与 TimoTV PNG；画布、元素数量、文字、资源 ID 和时间状态必须完全相同。基准截图要求 SSIM ≥ 0.995，并且按单通道差值大于 8 计算的差异像素不超过画面总像素的 0.5%。Three.js 抗锯齿样本可单独放宽到 SSIM ≥ 0.990 和差异像素 ≤ 1.0%，容差必须写入 fixture，不能在失败后临时调整。
- MP4 校验时长、分辨率、帧率、音轨、字幕时间和抽样帧。

开放式主题生成使用质量基准，不以一次模型随机输出作为结论。六个题材各运行三次，共 18 组同模型、同音色对照。TimoTV 必须做到：页面运行失败率为 0；最终未解决红色 lint 为 0；视觉审片最终通过率不低于帧言基线 5 个百分点以上；由三名不知道来源的评审按构图、风格一致性、口播对应、动画节奏和整体完成度各 1–5 分打分，TimoTV 总平均分与帧言差值不低于 -0.25，且在 18 组中被评为更好或持平的比例至少为 70%。

## 失败恢复

阶段检查点包括 Film Kit 单组件、页面初稿、每轮截图、审片结论、修正候选和全片审片。Worker 中断后从最后一个可信检查点继续，不重复调用已成功的模型或 TTS。

错误按阶段展示可执行恢复动作：重试当前组件、重画当前页、重新审片、接受非阻断问题或恢复全片检查。任何恢复动作都受 revision 和 jobId 所有权约束。页面程序崩溃、浏览器不可用、视觉模型不可用和 FFmpeg 失败分别记录，不用一个通用“制作失败”覆盖根因。

## 迁移阶段

### 阶段一：引擎与风格同步基线

建立上游清单和同步脚本，对帧言当前引擎、43 个风格目录、通用组件和工具做完整清点。修复当前 TimoTV 副本与上游的差异，使官方示例和固定源码关键帧达到视觉等价。

### 阶段二：Film Kit 和页面导演对齐

迁移 Film Kit 规划、生成、检查和降级逻辑；对齐页面提示词、上下文、lane 并发、页面检查轮次和修正信息。所有状态进入 Production 检查点。

### 阶段三：全片检查和渲染对齐

迁移全片联系表、跨页审片和定点重画。统一预览、审片和导出的运行时与资源解析，完成横版、竖版、2D、3D 和本地媒体基准。

### 阶段四：端到端质量验收

使用至少六个题材样本：科学原理、技术架构、管理读书、历史叙事、产品介绍和数据解释。每个样本在同模型和同音色下分别运行帧言与 TimoTV，固定人工盲评量表，记录失败与成本。全部门槛通过后，TimoTV 才默认启用对齐链路；之前保留 feature flag 和现有 V3 回退路径。

## 测试策略

- 清单测试：上游新增、删除或修改文件时 CI 明确失败并显示差异。
- 引擎测试：时序、镜头、固定随机、字体、媒体、Canvas、KaTeX、Three.js 和全部组件示例。
- 合同测试：Film Kit、页级检查、全片检查、指纹和 revision 所有权。
- 视觉回归：帧言与 TimoTV 固定源码关键帧对比。
- 集成测试：Film Kit → 页面生成 → lint → 审片 → 修正 → 全片检查 → MP4。
- 恢复测试：在每个检查点模拟 Worker 中断，确认不会重复付费调用或覆盖新 revision。
- 安全测试：页面程序不能访问网络、Node、父窗口、存储、任意路径和未登记资源。
- E2E：桌面和移动网页均能查看进度、处理失败、预览并下载最终 MP4；网页尺寸不影响视频像素。

新增行为遵循测试先行。引擎同步先用黑盒视觉基准证明等价，再做适配；导演迁移先建立固定模型输出 fixture，再接真实模型进行质量评估。

## 完成标准

以下条件必须全部满足：

1. TimoTV 的引擎清单与选定帧言提交一致，适配补丁有文档和自动验证。
2. 固定输入基准在横版、竖版、2D、3D、本地媒体和六种代表风格中达到约定像素容差。
3. Film Kit 实际用于跨页主体，并在恢复后复用已通过组件。
4. 页面 Agent 使用帧言同源视觉语法、真实 cue 时间、组件和镜头能力。
5. 每页执行运行时、lint、关键帧和独立视觉审片，最多两轮定点修正。
6. 全片执行跨页一致性检查，并只重画受影响页面。
7. 预览、seek、审片截图和 MP4 使用同一渲染函数；MP4 的时长、音轨、字幕和抽样帧校验通过。
8. 现有 TimoTV 项目、V1/V2/V3 页面、任务恢复和 revision 冲突保护继续工作。
9. 六类端到端主题按 18 组对照执行，并满足运行失败率 0、最终红色 lint 0、审片通过率差值不低于 -5 个百分点、盲评平均分差值不低于 -0.25、优于或持平比例至少 70%。
10. 在所有基准通过前，旧链路仍可通过 feature flag 恢复，不强制迁移已有项目。
