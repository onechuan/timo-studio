# TimoTV 连续动画与视觉审片

状态：用户已批准并完成实现；验证记录见 docs/verification.md。保留原项目，创建独立验证副本。外部视觉模型尚未配置，真实视觉判断准确性未验收。

## 目标与现状

保留项目管理、服务配置、火山 TTS、任务队列、修订号与任务所有权检查、逐页断点恢复。升级逐页画面表达和生成后的检查修正，两者共用同一份画面数据与时间轴。

当前 `packages/contracts/src/artwork.ts` 的 version 1 只有元素位置、尺寸、入场方式和 cueIndex。`packages/renderer/src/artwork.ts` 主要实现逐句入场；图形出现后缺少持续动作。`packages/agent/src/director/layout.ts` 做布局校验和调整，但没有读取渲染截图。`packages/core/src/production/runner.ts` 仅用 artwork 是否存在判断页面完成，增加审片后必须替换该判断。

参考帧言的 `packages/agent/prompts/PAGE.md`、`REVIEW.md` 和 `packages/agent/src/director.ts`：逐页创作、真实配音决定时间、统一绘图库、时间决定画面、浏览器测量、独立审片会话、有限修正轮数。参考这些职责边界，独立实现 TimoTV 接口和组件，不直接迁入其引擎或提示词全文。

## 路线选择

1. 推荐：统一绘图库 + 可组合场景对象 + 声音驱动的动画轨道 + 图片审片。扩展现有确定性渲染，获得连续动作，同时复用保存、预览和导出链路。
2. 直接生成任意页面 JavaScript：表达自由度最高，但需要额外隔离执行环境、代码诊断和依赖管理，首轮不采用。
3. 只扩充静态素材和提示词：改动最少，不能解决持续演示和生成质量缺少反馈的问题。

分两个连续里程碑交付：先让动画在预览与导出中一致运行，再把截图、审片与修正接入每页任务。第二步依赖第一步的时间采样接口，不拆成互不关联的系统。

## 绘图与动画

- 在 contracts 中增加 version 2，保留 version 1 的读取与渲染。旧作品不自动重绘；用户主动重绘的页面使用新格式。
- 对象由统一图元、现有插画、组合分组和标签组成；具有稳定 ID、父子关系和显式层级。不是固定模板选项，不要求所有题材都使用现有 22 个插画。
- 用有上限的关键帧轨道描述位置、缩放、旋转、透明度和颜色；支持组件状态切换，以及命令拓扑相同的路径插值。不同拓扑通过显式状态替换/交叉淡化，不把它宣称为任意形状变形。
- 组件声明支持的状态与参数。首批用容器液位、节点激活、流程传递三个可组合示例验证“变化表达含义”，不靠整个对象反复入场模拟演示。
- 时间锚点使用 cue ID、句内相对进度与偏移，编译成真实配音时间。当前只有句级时间，不声称具备词级对齐；更换声音后重新编译轨道和审片。
- 第一帧有主体，句间延续对象身份，页尾保留稳定画面。页内连续演示纳入首期；跨页共享对象和镜头连续运动留作后续扩展。
- 采用统一的纯函数 `evaluateScene(scene, time)` 计算状态，预览、截图和 MP4 使用同一结果。禁止用当前时钟、未设种子的随机数或 CSS 动画决定画面。正向播放、暂停、倒退和直接 seek 都能复现同一帧。
- 迁出独立的轨道求值、几何检查与图元绘制模块，避免继续把所有逻辑塞进 artwork.ts。保留现有包边界，不先拆新服务。

## 关键帧与两种检查

renderer 提供独立截图接口，复用导出的 HTML、字体、视口和 renderAt，等待字体与资源完成后采样。候选时间包含首帧、末帧、每个口播句中段、动作开始/中间/结束帧，去重并限制每页最多 24 帧；优先首末帧，其余名额先分配口播代表帧，再分配动作采样。口播数量超过剩余名额时沿时间轴均匀抽取，报告明确列出未覆盖的口播句。记录实际采样覆盖，关键帧检查不等于逐帧证明。

截图同时生成浏览器测量结果；检查包括变换后的越界、标题与字幕安全区侵占、文字实际溢出、不可见主体及运行错误。装饰背景与有意叠放不直接判为遮挡错误；对象相交先作为审片证据。运动路径的几何边界同时检查，降低仅看离散截图漏掉中途越界的风险。

独立视觉审片会话接收标有时间的截图、对应口播、画面意图和测量结果。输出结构化问题：sceneId、elementIds、时间点、严重度、证据和具体修正建议；每轮最多 5 个问题。只判断可读性、构图、遮挡、对象/动作与讲解对应关系及风格一致性，不因个人审美反复要求重画。

截图是必需输入。当前 JsonGenerator 只接收字符串，Pi 自定义模型配置声明 input: ['text']；需要新增有图片输入的审片接口。服务配置页增加独立“视觉审片模型”：服务商、模型、协议、地址、Key、启用状态。导演仍使用已有配置；复用现有凭据保存和脱敏规则，不把 Key 保存进作品。

没有配置图片模型时，继续允许制作与导出，界面明确标记“仅完成布局检查，未进行视觉审片”，提供配置入口与关键帧人工查看，不标成视觉通过。图片输入被拒绝、鉴权失败或网络异常显示“审片服务失败”，保留检查点；不静默降级成通过。首期不绑定未经确认的付费服务商。

## 修正闭环与恢复

每页流程：生成候选画面 → 校验/渲染 → 关键帧与测量 → 独立视觉审片 → 按问题修正 → 重新检查。首次候选后最多自动修正两次，每次均重新生成证据。报告属于检查它的内容版本，不能用旧通过结论覆盖新画面。

绘图 Agent 负责修改，审片 Agent 只返回问题。修正范围限定当前页的对象与动画，不修改已批准的分镜、口播、音频或其他页。需要改变讲述内容的问题交给用户，不自动改稿。

页面持久化字段包含 artworkHash、输入指纹（画幅/风格/口播和时间/绘图库版本/审片配置版本）、阶段、轮次、候选画面、关键帧引用、问题与最终结论。每次候选和审片后写检查点，仍受 revision + jobId 所有权约束。重试恢复未完成的检查/修正；artwork 存在不再意味着页面已经完成。

耗尽修正预算时：不可渲染的硬错误阻止合成；可渲染但有视觉问题的页面保留预览并标记“待人工确认”，允许用户明确接受当前页或重试本页。未配置视觉模型属于“未审片”，不等同“视觉失败”。Worker 崩溃后复用已持久化结果；外部模型请求与数据库写入不能原子化，故崩溃窗口可能重复一次请求，不承诺外部调用严格恰好一次。

新画面成功替换后使旧预览/MP4 失效；只重做目标页及合成产物。配音、字幕继续引用现有文件。换画幅/风格使绘图与审片失效，改口播重新制作受影响内容，换音色保留对象设计但使时间编译和审片失效。

审片报告与截图写在项目资产目录，以页面内容指纹和轮次隔离，通过已登记的文件白名单访问；API 增加 PNG/JPEG 类型，不开放任意目录读取。延续当前本地工作室权限范围，不借此引入多租户改造。

## 用户体验

每页显示“绘制中 / 检查中 / 修正中 / 已通过 / 未视觉审片 / 待确认 / 失败”。查看报告可见关键帧、问题对应时间和修改结果；点击时间跳到预览。提供重试审片、仅修复本页、接受当前页三个明确操作。沿用当前颜色和布局，不增加通用诊断面板。

设置页的识图能力检查应验证实际图片输入能被接口接收；配置存在不代表能力已验证，也不以请求成功保证判断准确。未提供可用配置前，以测试替身验证流程，以本机真实截图验证渲染，不宣称真实模型审片已经验收。

## 验收与实施范围

1. 同一对象在三句口播之间完成移动、状态变化与路径形变；切换状态不是删除整页重建静态卡片。横竖版都有示例。
2. 同一时间点在预览、截图和导出渲染中保持相同画面；反向 seek、重复求值与暂停不改变结果。
3. 构造文字截断、字幕遮挡、动作中途越界和讲解对象缺失样例，分别验证确定性检查与审片问题流转；不能用模拟审片结果证明真实模型识别能力。
4. 模拟审片退回后只修正目标页，第二次截图对应新 hash；已通过页面不重复绘制。中途终止后可从检查点继续，旧 Worker 不得覆盖新任务。
5. 未配置、配置失败、轮数耗尽和人工接受有独立状态。实际图片模型配置好后，再进行有限样例的真实视觉识别与修正验收。
6. 使用现有牛肉汤项目的副本做集成演示，保留原项目与已导出的 MP4；验证复用音频/字幕的哈希不变。导出能播放和下载。

预计修改落点：contracts（版本协议、审片数据与设置），renderer（统一图元、轨道、截图与测量），agent（绘图与审片接口、阶段规则），core/db（状态与检查点），worker（能力组装），api（设置和报告资源），web（页级状态与报告），tests（动画、恢复、接口与浏览器测试）。

不包含移动 App、视频素材剪辑、全新绘图模型服务、任意代码执行或跨页镜头系统。验收重点是连续演示与可观察的审片修正闭环。
