# 帧言参考规则的离线验证

日期：2026-11-08。本记录区分代码事实与独立 Agent 的单次模拟；未调用 DeepSeek、火山 TTS，不是实际服务商的效果测评，也不是多次独立采样实验。

## 优化前

独立 Agent 读取旧版组合提示词、director 和 renderer 后执行三个场景：

1. **通用讲解，15 秒，主题要求一句核心回答。** 乱序资料为“可用颜色分类；记录任务不代表选择今天要做的任务；每周回看清单”。实际模拟输出：“清单为什么越写越长？因为记录任务不等于安排今天。颜色能分类，回看能整理。但今天仍然要先选一件事。”它选中了核心信息，但没有遵守一句要求。代码确认 SCRIPT 未收到 topic，且旧提示词要求每页 4–8 句。
2. **科普，VO 与 Visual 混排，topic 要求逐字保留。** 原 VO 为“杯子没有漏水。空气中的水蒸气遇到足够冷的杯壁，凝结成水滴。所以，杯壁上的水来自周围空气。”模拟增加了“冷杯外面的水是哪里来的？”，把“杯子没有漏水。”改成“杯子并没有漏水。”。没有念 Visual，但原稿保留失败。代码确认逐字要求可能因 topic 缺失而丢失；提示词的开场提问、句数与原稿规则没有清晰优先级。
3. **产品介绍，30 秒震撼宣传，仅有“支持标签分类”。** 模拟没有虚构数字或功能，但 visual 写了卡片分组动画。代码确认 renderer 不消费 visual 绘图，只按页进度展示节点与 beats 短标签；无法实现该具体动作。本次没有观察到夸张事实失败，因此保留原有事实约束，仅强化具体表达方式和能力边界。

## 实现与自动验证

- 补回 SCRIPT user JSON 中的 topic；新增回归用例确认原始主题、资料和批准分镜全部传递。
- 共享导演/口播方法按阶段加载；已有方向隔离测试同时验证共享方法不会跨阶段加载。
- 新增/扩展测试先出现 5 项失败，实现后导演测试 7 项通过。
- Agent 构建、测试 TypeScript 检查通过；全单元测试 64 项通过、1 项可选媒体测试跳过。
- 制作集成测试 4 项通过：注入模型，真实数据库、队列、Worker、本地语音、Chrome 与 FFmpeg，覆盖编译后加载和原制作流程。

自动测试不评价文案的吸引力，也不证明模型必然遵守提示词。原稿保持、短片取舍和事实约束仍需要内容验收；真实时长仍由 TTS 测量。

## 优化后独立场景检查

另一位独立 Agent 使用相同三类场景读取优化后的组合规则，各执行一次离线模拟：

1. 通用讲解输出一个 cue：“因为记录任务并不等于选定今天要完成的任务，只记录、不选择，清单就会越写越长。”遵守一句要求，没有照材料顺序逐条复述，也没有宣称精确 15 秒。
2. 科普输出三个 cue：“杯子没有漏水。”“空气中的水蒸气遇到足够冷的杯壁，凝结成水滴。”“所以，杯壁上的水来自周围空气。”该 Agent 用本地字符串比较确认拼接后与三行 VO 完全一致，Visual 未进入口播。
3. 产品输出两个 cue：“支持标签分类。”“按标签，把相关内容归在一起。”无虚构产品名、数字、额外功能或购买号召；拍点使用“标签分类”“同类归组”，没有承诺自由动画或精确 30 秒。

静态复核未发现这三个场景的阻断性规则冲突。仍有既存限制：运行时代码检查 schema 与场景 ID 顺序，尚未强制比较原稿全文或批准分镜的 title/visual/beats；这些内容的遵循依赖模型与人工审批。本轮没有增加这些强制校验，也未将单次离线模拟表述为稳定遵循率。
