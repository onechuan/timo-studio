# TimoTV 创作方法适配记录

本轮按用户已确认的建议实现：借鉴本地 huobao-drama 提示词中的节拍、可见动作与一致性方法，重新编写为口播矢量动画规范。

## 已落地

- 分镜：现有 say / visual / beats 分别承载解释关系、空间与结果、动作顺序；按理解节拍拆页，因果链能在一页讲清时保持完整。
- 口播：新稿跟随批准拍点，补充原因与条件；逐字原稿规则不变。
- 绘图：新增 visual-storytelling Skill，在真实 TTS 时间之后加载。页内使用同一对象轨道，跨页参考 previousArtwork 末态显式定义初态，修复关注问题对象及关联轨道。
- Prompt：保留 v2 协议、完整插画语义和安全区约束；首行示例补齐 tracks，删除重复构图方法及过度绑定单一汤碗主题的示例。
- 产品宣传：区分功能概念示意与实际产品交互，避免动画暗示未经确认的自动化或性能。
- 文档：同步连续动画和已实现的截图／独立模型审片能力，消除旧说明。

## 设计边界

不更换 Pi，不迁移 Mastra 工具，不增加资产库、三视图、生图或视频生成服务。规划与口播不生成时间；绘图只使用输入的真实 cues。跨页状态是生成规范，不是引擎自动持久化状态。已有项目没有被重新生成。

## 优化前观察

独立只读检查按旧规则模拟五个案例，未调用真实模型服务：

1. 冷杯：已有“杯体 → 空气示意点 → 水滴”，但不明确要求初态与凝结后的末态。
2. 产品：已有事实约束；标签分组动画仍可能被理解成未经确认的自动交互，三秒切镜缺少明确转译规则。
3. 跨页液位：已有外观复用和 previousArtwork 输入，但从上一页末值 0.55 开始需要模型主动推断，规则未明确要求。
4. 逐字 VO：现有保留规则已充分，没有发现需要重写的缺口。
5. 标签修复：已有反馈与有效轨道保留规则，补充只修关联对象及运动中途问题有助于明确边界。

这些是静态模拟观察，不是已证实的 DeepSeek 失败率或质量基准。

## 已执行验证

- 修改前导演与绘图导演测试：29 项通过。
- 修改后导演、绘图、动画、渲染、审片相关测试：7 个文件，58 项通过。
- agent 包 build、typecheck 和 git diff --check 通过。
- 编译后的运行时以模型替身验证：新 Skill 不进入分镜或口播；绘图首次调用与校验重试均加载 Skill；真实 cue 时间及文本保留；完整 v2 组件和液位轨道通过校验。未调用外部模型、TTS 或数据库。
- 开发服务观察到 agent 构建产物变化，API 和 Worker 自动重载，Worker 输出 ready。
- 独立只读复核对上述五个案例进行优化后模拟，未发现阻断性协议冲突；发现 PAGE 旧文“仅用 path/ellipse/rect”与可控组件能力不一致，已统一为“自绘图元与可控组件”；sequence 构图也明确允许同一主体的连续状态，避免为套模板复制主体。

## 效果验证边界

本轮没有调用付费模型生成视频，也没有声称画面质量已得到量化提升。提示词场景模拟用于检查规则覆盖和冲突；真实效果仍需同一主题、模型和设置下比较生成视频，并结合实际截图审片。
